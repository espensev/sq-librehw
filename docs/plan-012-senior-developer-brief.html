Why Plan‑012

Separate orchestration from rendering surfaces.

MainForm currently knows every concrete presentation API. The target adds typed forwarding and one ordered coordinator while keeping interaction policy where it already works.

Current shape · verified baseline

Direct concrete edges

No defect is claimed here. The issue is reviewability and substitution cost: operational calls are interleaved with behavior that must remain MainForm‑owned.

Plan‑012 target · planned

One coordinator, four narrow ports

The boundary is deliberately thin. It does not virtualize the whole tree, convert live sensors to a new DTO, or move policy into a second MainForm.

Tree

adapter owns

Redraw/invalidation only. MainForm retains model attachment, canonical order, columns, scaling, selection, keyboard/mouse handling, hit targets, scrollbars, and UI Automation.

Plot

adapter owns

Exact control identity, reset callback, settings projection, sensor/color/stroke forwarding, text scales, and redraw. MainForm retains show/location menu and control parenting.

Tray

adapter owns

Redraw, main icon, membership, balloon flag, command events, and disposal forwarding. SystemTray retains settings, hardware subscriptions, icons, and native resource ownership.

Gadget

adapter owns

Optional availability, visibility, redraw, membership, command event, and disposal forwarding. Windows-only construction and the legacy renderer remain unchanged.

Senior review guide

The sharp edges are explicit.

The plan should be rejected if the adapter becomes a policy owner, if the tree is wholesale abstracted, or if the refactor requires a surface-class or external-contract change.

Risk: a second MainForm appears behind a “coordinator” name
Mitigation: the coordinator exposes operations only. MainForm retains construction, UI thread, menus, layout/input, timers, lifecycle, settings, hardware, and all decisions about when an operation occurs.
Risk: tree abstraction breaks high-value interaction behavior
Mitigation: Plan‑012 does not proxy selection, columns, auto-fit, keyboard/mouse interaction, scrollbars, accessibility objects, or canonical Node/TreeModel order. The tree port is intentionally narrow.
Risk: wrapper disposal duplicates native ownership
Mitigation: adapters forward disposal to the existing tray/gadget owners exactly once, gadget before tray. WinForms retains normal control disposal for tree and plot.
Risk: “executed” or a healthy live sample is read as deployed
Mitigation: campaign status, source implementation, person acceptance, candidate creation, promotion, and live health are reported as separate facts everywhere—including this page.

Handoff

Start with the contract, not MainForm.

The senior developer should review the canonical plan and AS contract first. Implementation begins only with AS in an isolated worktree. AT, AU, and AV follow after dependency‑ordered integration and green gates. The rollback is source-only: revert AU, then AT, then AS back to 9d4786c. No operational rollback packet is involved.

Remaining human gate: Plan‑001 A1 attended normal-user smoke remains separate and person-only. Plan‑012 itself also cannot be called accepted or deployed by automation.
